# UNIT 1: CLOUD COMPUTING

## 1.1 Define Cloud Computing (also: Why is it important?)

**Definition:** Cloud computing means delivering computing services — such as servers, storage, databases, networking, software and analytics — over the **Internet ("the cloud")** on a **pay-as-you-use** basis, instead of owning and maintaining your own hardware.

**Simple example:** Instead of buying a big computer to store photos, you use Google Drive or iCloud. You use storage from a company's data centre and pay only for what you use.

**NIST definition (good to write):** Cloud computing is a model for enabling convenient, on-demand network access to a shared pool of configurable computing resources (networks, servers, storage, applications, services) that can be rapidly provided with minimal management effort.

**Why it is important:**
1. **Saves cost** – no need to buy expensive servers; pay only for use.
2. **Scalability** – increase or decrease resources in minutes.
3. **Access from anywhere** – only an Internet connection and a device are needed.
4. **Fast deployment** – a server can be ready in minutes.
5. **Reliability** – backup and disaster recovery are available.
6. **Automatic updates** – the provider handles software and security patches.
7. **Supports modern tech** – AI, Big Data, IoT and mobile apps run on the cloud.

---

## 1.2 Operations of Cloud Computing

Cloud computing works through a set of basic operations:

1. **Provisioning (Deployment):** Giving users the resources (VM, storage, network) when they ask for them.
2. **Scaling (Elasticity):** Automatically increasing or decreasing resources as the load changes (scale-up/scale-out, scale-down/scale-in).
3. **Storage:** Storing data on remote servers (object, block and file storage).
4. **Computing / Processing:** Running applications on virtual machines or containers.
5. **Networking:** Connecting cloud resources and users through virtual networks, load balancers and firewalls.
6. **Monitoring and Metering:** Tracking usage, performance and health; this is used for billing ("pay-per-use").
7. **Backup and Recovery:** Making copies of data and restoring them after failure.
8. **Security and Access Management:** Authentication, authorisation, encryption and identity management.
9. **Migration:** Moving data and applications from on-premise to the cloud (or between clouds).
10. **Resource Management / Load Balancing:** Sharing the work across servers so no server is overloaded.

## 1.4 Characteristics (Features) of Cloud Computing

1. **On-demand self-service:** User gets resources (server, storage) automatically without calling the provider.
2. **Broad network access:** Services are available over the Internet from any device (mobile, laptop, tablet).
3. **Resource pooling (Multi-tenancy):** The provider's resources are shared among many users using virtualization.
4. **Rapid elasticity (Scalability):** Resources can be increased or decreased quickly according to demand.
5. **Measured service (Pay-per-use):** Usage is monitored and the user pays only for what is used.
6. **High availability and reliability:** Data is replicated across multiple locations, so service continues even if one fails.
7. **Cost effective:** No upfront hardware cost; low maintenance.
8. **Automation and easy maintenance:** Updates, patching and backup are done by the provider.
9. **Security:** Encryption, firewalls, access control.
10. **Performance:** Powerful hardware gives fast processing.

---

## 1.5 Advantages of Cloud Computing

1. **Cost saving** – no capital expenditure; pay-as-you-go.
2. **Scalability and flexibility** – grow or shrink instantly.
3. **Accessibility** – work from anywhere, any device.
4. **Data backup and disaster recovery** – data is safe even if local machine fails.
5. **Automatic software updates** – always the latest version.
6. **Collaboration** – many people can work on the same document (Google Docs).
7. **Speed and agility** – quick deployment of new apps.
8. **Environment friendly** – shared resources use less energy.
9. **Security** – strong security by big providers.
10. **Focus on business** – no need to manage IT infrastructure.

*(Disadvantages, if asked as extra: internet dependency, security/privacy concerns, vendor lock-in, limited control, downtime risk.)*

## 1.6 Compare Cloud Computing and Grid Computing

**Grid computing** = many computers (often in different places) are linked together to work on **one big task** (like a super computer) — e.g., SETI@home, scientific research.

| Point | Cloud Computing | Grid Computing |
|---|---|---|
| Purpose | Provides on-demand services (storage, apps, servers) to many users | Solves one large, complex problem by sharing computing power |
| Architecture | Centralised control by a provider | Decentralised / distributed, no single owner |
| Resources | Virtualised and shared | Physical machines contributed by many organisations |
| Users | General public, businesses | Scientists, researchers, large organisations |
| Payment | Pay-per-use (commercial) | Usually free / collaborative (non-commercial) |
| Scalability | Highly scalable and elastic | Less elastic, scalable by adding nodes |
| Access | Via Internet / web browser | Via special grid software/middleware |
| Task type | Many small independent services | Few large parallel tasks (batch jobs) |
| Examples | AWS, Azure, Google Drive | SETI@home, CERN LHC grid |
| Virtualization | Heavily used | Rarely used |

## 1.8 Types of Clouds in Detail (with diagram)

Clouds are classified by **deployment model** (who owns and who can use them):

```
                     CLOUD DEPLOYMENT MODELS
   +-----------+   +-----------+   +-----------+   +-----------+
   |  PUBLIC   |   |  PRIVATE  |   |  HYBRID   |   | COMMUNITY |
   |  CLOUD    |   |  CLOUD    |   |  CLOUD    |   |  CLOUD    |
   +-----------+   +-----------+   +-----------+   +-----------+
   Open to all     One org only    Public+Private  Shared by orgs
   (Internet)      (Intranet)      connected       with common goal

   Hybrid Cloud:
   +----------------+   secure link   +----------------+
   | Private Cloud  | <-------------> |  Public Cloud  |
   | (sensitive     |                 | (normal/peak   |
   |  data)         |                 |  workload)     |
   +----------------+                 +----------------+
```

### 1. Public Cloud
- Services offered over the Internet by a third-party provider to anyone.
- Resources are shared among many customers (multi-tenant).
- **Advantages:** low cost, no maintenance, high scalability, pay-per-use.
- **Disadvantages:** less control, security/privacy concerns.
- **Examples:** AWS, Microsoft Azure, Google Cloud.

### 2. Private Cloud
- Cloud infrastructure used by **only one organisation**, in its own data centre or hosted privately.
- **Advantages:** high security, full control, customisation, compliance.
- **Disadvantages:** high cost, needs skilled staff, limited scalability.
- **Examples:** VMware vCloud, OpenStack, banking clouds.

### 3. Hybrid Cloud
- Combination of public and private clouds connected together.
- Sensitive data stays in the private cloud; normal workload or sudden peak load goes to the public cloud ("cloud bursting").
- **Advantages:** flexibility, cost-security balance, scalability.
- **Disadvantages:** complex to manage, integration issues.
- **Example:** A company stores customer records privately but runs its website on AWS.

### 4. Community Cloud
- Shared by several organisations with common concerns (security, compliance, mission) — e.g., government departments, universities, hospitals.
- **Advantages:** cost sharing, common policies.
- **Disadvantages:** limited users, shared bandwidth, hard to decide on shared policy.

*(Some books add Multi-cloud = using several different public cloud providers together.)*

## 1.9 Cloud Computing Architecture (with diagram) and Technologies

**Meaning:** Cloud architecture is the way different components (front end, back end, network, services) are combined to deliver cloud services.

```
   +---------------------------------------------------------+
   |                    FRONT END (Client side)              |
   |   Web browser | Mobile app | Desktop | Thin client      |
   +---------------------------+-----------------------------+
                               |
                      INTERNET / NETWORK
                               |
   +---------------------------v-----------------------------+
   |                     BACK END (Cloud side)               |
   |  +---------------------------------------------------+  |
   |  |  Management / Cloud Services Layer                |  |
   |  |  (SaaS | PaaS | IaaS)                             |  |
   |  +---------------------------------------------------+  |
   |  |  Application  |  Runtime Cloud  |  Security       |  |
   |  +---------------------------------------------------+  |
   |  |  Management / Middleware (load balancing,         |  |
   |  |  scheduling, monitoring, billing)                 |  |
   |  +---------------------------------------------------+  |
   |  |  Virtualization Layer (hypervisor, VMs)           |  |
   |  +---------------------------------------------------+  |
   |  |  Infrastructure: Servers | Storage | Network      |  |
   |  +---------------------------------------------------+  |
   +---------------------------------------------------------+
```

### Components
**A. Front End (Client Infrastructure):** What the user sees and uses — browser, mobile app, or client software that connects to the cloud (e.g., Chrome to open Gmail).

**B. Back End (Cloud Infrastructure):** Run by the provider. It contains:
1. **Application:** The software or platform the client accesses.
2. **Service:** The core of the cloud; provides SaaS, PaaS, IaaS services.
3. **Runtime Cloud:** Provides the execution/runtime environment for virtual machines.
4. **Storage:** Stores and manages large amounts of data flexibly.
5. **Infrastructure:** Physical hardware — servers, storage devices, network devices, data centres.
6. **Management:** Controls and coordinates back-end components (middleware).
7. **Security:** Protects data via authentication, encryption, firewalls, backups.
8. **Internet:** The medium (network) between front end and back end.

### Technologies behind Cloud Computing
1. **Virtualization** – creates multiple virtual machines on one physical server.
2. **Service-Oriented Architecture (SOA)** – applications built as reusable services.
3. **Grid/Distributed computing** – uses many machines for processing.
4. **Utility computing** – metered, pay-per-use model.
5. **Web services and APIs** – SOAP, REST for communication.
6. **Containers and orchestration** – Docker, Kubernetes.
7. **Multi-tenancy** – many users share the same resources safely.
8. **Broadband / high-speed networks and data centres.**

## 1.10 Cloud Service Models — IaaS, PaaS, SaaS (and types of cloud computing services)

```
        SaaS  -> Ready-to-use software (Gmail, Salesforce)        <- End users
        PaaS  -> Platform to build apps (Google App Engine)        <- Developers
        IaaS  -> Servers, storage, network (AWS EC2)               <- IT administrators
```

### 1. IaaS — Infrastructure as a Service
- Provider gives **virtual hardware**: virtual machines, storage, networks, IP addresses, load balancers.
- User installs the OS, middleware and applications and manages them. Provider manages physical hardware.
- **Users:** system administrators, network architects.
- **Advantages:** no hardware purchase, scalable, pay-as-you-go, full control over OS.
- **Disadvantages:** user must manage OS, security patching; needs technical skill.
- **Examples:** Amazon EC2, S3, Microsoft Azure VMs, Google Compute Engine, DigitalOcean.

### 2. PaaS — Platform as a Service
- Provider gives a **ready platform** (OS, runtime, database, web server, development tools) to **build, test and deploy** applications.
- User manages only the application and data.
- **Users:** software developers.
- **Advantages:** fast development, no need to manage servers or OS, built-in tools, easy team collaboration.
- **Disadvantages:** less control over the platform, vendor lock-in, limited languages supported.
- **Examples:** Google App Engine, Heroku, AWS Elastic Beanstalk, Microsoft Azure App Service.

### 3. SaaS — Software as a Service
- Provider gives **complete software** over the Internet through browser/app on subscription; nothing to install.
- Provider manages everything: infrastructure, platform and application.
- **Users:** end users and businesses.
- **Advantages:** no installation, automatic updates, accessible anywhere, low cost, easy to use.
- **Disadvantages:** less customisation, depends on internet, data security concerns.
- **Examples:** Gmail, Google Docs, Microsoft 365, Salesforce, Dropbox, Zoom.

### Comparison Table
| Point | IaaS | PaaS | SaaS |
|---|---|---|---|
| Full form | Infrastructure as a Service | Platform as a Service | Software as a Service |
| Provides | Virtual hardware | Development platform | Ready software |
| Target user | IT admins | Developers | End users |
| User controls | OS, apps, data | Apps, data | Only settings/data |
| Provider controls | Hardware, virtualization | Hardware, OS, runtime | Everything |
| Example | AWS EC2 | Google App Engine | Gmail |

(Newer models: **FaaS / Serverless** — e.g., AWS Lambda; **DBaaS**; **CaaS**.)

## 1.11 Virtualization — Definition, Types, Role in Cloud

**Definition:** Virtualization is the technique of creating a **virtual (software-based) version** of a physical resource such as a server, storage device, network or operating system. It lets **one physical machine run multiple virtual machines (VMs)**, each with its own OS and applications. This is done by software called a **hypervisor** (VMware ESXi, Hyper-V, KVM, VirtualBox).

```
   Without virtualization          With virtualization
   +----------+                    +-----+ +-----+ +-----+
   | 1 OS     |                    | VM1 | | VM2 | | VM3 |
   | 1 App    |                    +-----+-+-----+-+-----+
   | Server   |                    |     HYPERVISOR      |
   +----------+                    +---------------------+
                                   |  Physical Hardware  |
                                   +---------------------+
```

### Types of Virtualization
1. **Hardware (Server) Virtualization:** One physical server is split into many VMs using a hypervisor. (Type 1 – bare metal: ESXi; Type 2 – hosted: VirtualBox.)
2. **Operating System Virtualization:** Many isolated user spaces (containers) share the same OS kernel — Docker, LXC.
3. **Storage Virtualization:** Many physical storage devices are pooled and shown as one single storage — SAN, NAS.
4. **Network Virtualization:** Physical network resources are combined into a virtual network — VLAN, VPN, SDN.
5. **Application Virtualization:** An application runs on a user's device without being fully installed — Citrix, Microsoft App-V.
6. **Desktop Virtualization:** Desktop environment is hosted on a central server and accessed remotely — VDI.
7. **Data Virtualization:** Data from different sources is accessed as one without moving it.

### Explanation of one type — Server (Hardware) Virtualization
- A hypervisor is installed on the physical server and divides CPU, RAM and disk into several VMs.
- Each VM works like an independent computer (can run Windows, Linux, etc.).
- **Benefits:** better hardware utilisation (from ~15% to 80%), lower cost, easy backup/migration, isolation (one VM crash doesn't affect others), faster provisioning.

### Role of Virtualization in Cloud Computing
1. **Resource pooling:** It makes it possible to share one hardware among many customers (multi-tenancy).
2. **Elasticity/scalability:** New VMs can be created or removed in seconds.
3. **Cost reduction:** Fewer physical servers needed.
4. **Isolation and security:** Each user's VM is separate.
5. **Fast provisioning:** VM templates enable instant deployment.
6. **Disaster recovery:** VM snapshots and live migration.
7. **Efficient use of hardware and energy.**
Therefore virtualization is the **foundation/backbone** of cloud computing (especially IaaS).

## 1.12 Short Definitions: Cloud Computing, SOA, Cloud Hosting, AWS

1. **Cloud Computing:** Delivery of computing services (servers, storage, software, databases) over the Internet on a pay-as-you-use basis (see 1.1).
2. **SOA (Service-Oriented Architecture):** A software design style where an application is built from small, independent, reusable **services** that communicate over a network using standard protocols (SOAP, REST, XML/JSON). Example: a payment service and a login service reused by many apps. It is a base technology for cloud.
3. **Cloud Hosting:** A type of web hosting in which a website or application is hosted on a **network of many connected virtual/physical servers** (cloud) instead of one single server. If one server fails, another takes over; resources can be scaled easily; you pay for what you use. Examples: AWS, DigitalOcean, Google Cloud hosting.
4. **AWS (Amazon Web Services):** The world's largest cloud platform from Amazon, launched in 2006, offering 200+ services like **EC2** (virtual servers), **S3** (storage), **RDS** (database), **Lambda** (serverless), **VPC** (network). It works on pay-as-you-go pricing and has data centres across many regions worldwide.

# UNIT 2: AUGMENTED REALITY (AR) & VIRTUAL REALITY (VR)

## 2.1 Define: Reality, Virtual Reality, Augmented Reality, Navigation

1. **Reality:** The real, physical world that we see, hear, touch and experience with our senses without any computer help.
2. **Virtual Reality (VR):** A computer-generated, fully immersive 3D environment that replaces the real world; the user wears a headset (e.g., Oculus/Meta Quest) and feels present inside a virtual world.
3. **Augmented Reality (AR):** Technology that adds (overlays) digital information — images, text, 3D objects — on top of the **real world** view using a phone camera or smart glasses. Example: Pokémon GO, IKEA Place, Snapchat filters.
4. **Navigation:** Process of finding and following a route from one place to another. In VR/AR it means moving through a virtual environment (walking, teleporting, flying) or getting directions overlaid on the real world (AR navigation like Google Maps Live View). Also called **wayfinding**.

---

## 2.2 Virtual Reality (VR) in Detail (also: Technology and features)

**Definition:** VR is a computer-generated simulated environment that gives the user a feeling of being **physically present** inside a 3D virtual world. The user can look around, move and interact with objects in real time. Real world is completely blocked out.

**How it works:** Head-mounted display (HMD) shows two slightly different images (one per eye) to create 3D depth; sensors track head and hand movement; the computer updates the view instantly.

```
  User -> [Head Mounted Display + Controllers + Sensors]
              |  head/hand movement tracked
              v
        [Computer / Console / Standalone processor]
              |  renders 3D world in real time
              v
        [Display + Audio + Haptic feedback to user]
```

**Technology / Hardware components:**
1. **Head-Mounted Display (HMD):** Screens + lenses (Oculus Quest, HTC Vive, PlayStation VR).
2. **Tracking sensors:** Gyroscope, accelerometer, magnetometer, cameras, base stations — track head, body and hand position (6 Degrees of Freedom).
3. **Input devices:** Hand controllers, gloves, treadmills, voice, eye tracking.
4. **Processing unit:** Powerful PC, console or built-in chip with GPU.
5. **Audio:** 3D spatial sound headphones.
6. **Haptic devices:** Vibrating gloves/suits give touch feeling.
7. **Software:** 3D engines (Unity, Unreal), VR SDKs.

**Types of VR:**
- **Non-immersive** (computer screen, e.g., video games).
- **Semi-immersive** (flight simulators, large screens).
- **Fully immersive** (HMD with full tracking).

**Key Features:**
1. **Immersion** – feeling of being inside the virtual world.
2. **Interaction** – user can touch/move objects.
3. **Presence** – feeling of "being there".
4. **Real-time response** – instant updates, low latency.
5. **3D visualisation** and **sensory feedback** (sight, sound, touch).
6. **Imagination/Simulation** – can recreate any place or situation.

**Applications:** Gaming, education, medical training, military training, virtual tourism, real-estate walkthroughs, therapy.

## 2.3 Augmented Reality (AR) in Detail (also: Technology and features)

**Definition:** AR is a technology that **superimposes computer-generated content** (text, images, 3D models, sound, video) on the **user's view of the real world** in real time, so real and virtual objects exist together. The real world remains visible.

**Examples:** Pokémon GO, Snapchat/Instagram filters, IKEA Place (see furniture in your room), Google Lens, AR navigation, virtual try-on of glasses/makeup.

```
   Real World  --->  [Camera/Sensors]  --->  [Processor + AR software]
   (what you see)                                    |
                                                     v
            Real view + Digital overlay  <---  [Display: phone / smart glasses]
```

**Technology / Components:**
1. **Sensors and cameras:** Capture the real environment (camera, GPS, gyroscope, accelerometer, depth sensor, LiDAR).
2. **Processing unit:** CPU/GPU recognises surfaces and objects, computes position.
3. **Display:** Smartphone/tablet screen, smart glasses (HoloLens, Google Glass), HUD.
4. **Software/SDK:** ARCore (Android), ARKit (Apple), Vuforia.
5. **Tracking and registration:** Marker-based, markerless (SLAM), location-based, projection-based.

**Types of AR:**
- **Marker-based** (QR/image trigger)
- **Markerless** (uses SLAM/GPS)
- **Projection-based** (projects light on surfaces)
- **Superimposition-based** (replaces view with augmented object)

**Features:**
1. Combines real + virtual world.
2. Real-time interaction.
3. Accurate 3D registration (virtual object fixed correctly in real space).
4. Works on common devices (smartphones).
5. Does not isolate user from the real world.
6. Context-aware information.

**AR vs VR in one line:** AR *adds* to reality; VR *replaces* reality.

## 2.5 Mixed Reality (MR) with Example

**Definition:** Mixed Reality is a technology that **merges the real and virtual worlds** so that physical and digital objects **co-exist and interact with each other in real time**. It is a blend of AR and VR (sometimes called "hybrid reality").

- In AR, digital objects only sit on top of the real world (cannot really interact with it).
- In MR, digital objects **understand the real environment** — a virtual ball can bounce off your real table, hide behind a real wall, and you can move it with your hands.

```
 Real World <---------- AR ---------- MR ---------- VR ----------> Virtual World
 (Reality-Virtuality Continuum by Milgram)
```

**Requirements:** Advanced sensors, spatial mapping, depth cameras, powerful processing, special headsets (**Microsoft HoloLens 2, Magic Leap**).

**Example:**
- A surgeon wearing HoloLens sees a 3D hologram of a patient's organs placed over the real patient and rotates it with hand gestures.
- Engineers see a virtual engine model placed on a real workbench and walk around it.
- Games where virtual characters hide behind real furniture of your room.

**Features:** Real-virtual interaction, spatial awareness, gesture/voice control, shared collaboration.

## 2.11 Visualization Techniques for VR and AR

Visualization techniques are the **methods to display and render** virtual information so the user sees it realistically.

### Visualization techniques for Virtual Reality
1. **Stereoscopic display (stereo vision):** Two slightly different images shown one to each eye to create 3D depth.
2. **Head-Mounted Display (HMD):** Screens and lenses placed in front of eyes; image changes with head movement.
3. **CAVE (Cave Automatic Virtual Environment):** A room whose walls/floor are projection screens; user wears 3D glasses and is surrounded by images.
4. **Large-screen / Immersive projection displays:** Dome, wall or curved-screen projections for groups.
5. **Desktop / Window-on-world VR:** 3D scene on a normal monitor (non-immersive).
6. **Head tracking and motion parallax:** The view updates according to head position.
7. **Real-time 3D rendering (rasterisation / ray tracing):** GPU generates scenes at 60-120 fps.
8. **Spatial (3D) audio and haptics:** Complement visualization for realism.
9. **Foveated rendering:** Draws high detail only where the eye looks (with eye tracking) to save processing.

### Visualization techniques for Augmented Reality
1. **Video see-through (video mixing):** Camera captures real world; computer adds graphics; combined view shown on screen (smartphone AR).
2. **Optical see-through:** User sees the real world directly through transparent glasses; graphics projected on the lens (HoloLens, Google Glass).
3. **Projection-based (Spatial AR):** Digital images are projected directly on real objects/surfaces.
4. **Head-Up Display (HUD):** Information displayed on windshield/visor (cars, fighter jets).
5. **Handheld display AR:** Phone/tablet used as a "window" to augmented world.
6. **Marker-based / Markerless overlay:** QR/image or SLAM/GPS tracking to place 3D objects.
7. **Retinal projection:** Light beamed directly on the retina (advanced).

## 2.12 AR Systems and their Functionality

**AR system:** A combination of hardware and software that captures the real world, understands it, and overlays digital content in real time.

```
 [Real World]
     |
 1. SENSING   (camera, GPS, IMU, LiDAR, depth sensor)
     |
 2. TRACKING & REGISTRATION  (find position/orientation of device; align virtual with real)
     |
 3. PROCESSING / SCENE UNDERSTANDING  (recognise surfaces, objects, lighting)
     |
 4. RENDERING (generate 3D graphics, correct perspective & lighting)
     |
 5. DISPLAY   (phone, smart glasses, HUD)
     |
 6. INTERACTION (touch, gesture, voice, gaze)
     |
 [User sees real + virtual combined]
```

### Main components
1. **Input devices/sensors:** Camera, GPS, compass, accelerometer, gyroscope, depth sensors.
2. **Processor:** CPU/GPU to run AR algorithms (SLAM, object detection).
3. **Display devices:** Smartphone, HMD, smart glasses, projectors.
4. **AR software:** ARCore, ARKit, Vuforia, Unity — create and manage AR content.
5. **Network/Cloud:** Provides data, maps, and heavy computing.

### Functionalities of AR
1. **Detection and recognition** of images, markers, faces and objects.
2. **Tracking** of user's position and movement (6DoF).
3. **Registration** — accurately aligning digital objects with real world.
4. **Overlaying/Rendering** of 3D models, text and videos.
5. **Surface/plane detection** and environment mapping (SLAM).
6. **Occlusion and lighting estimation** — virtual objects hide behind real ones and match lighting.
7. **User interaction** through touch, gestures, voice and gaze.
8. **Real-time information retrieval** (translation, navigation, product info).
9. **Collaboration/sharing** of AR experience among users.

## 3.1 Define Artificial Intelligence and Machine Learning with Example

**Artificial Intelligence (AI):** The branch of computer science that makes machines **think and act like humans** — able to learn, reason, solve problems, understand language and make decisions. (Coined by John McCarthy, 1956.)
- *Example:* Siri/Alexa voice assistants, chess-playing computer, self-driving car, chatbots.

**Machine Learning (ML):** A **subset of AI** in which computers **learn from data** and improve their performance with experience **without being explicitly programmed** with fixed rules. (Arthur Samuel, 1959.)
- *Example:* Email spam filter learns from thousands of spam/non-spam emails and then classifies new emails; Netflix recommending movies; predicting house price from past data.

**Relation:** `AI ⊃ Machine Learning ⊃ Deep Learning`

| Point | AI | ML |
|---|---|---|
| Scope | Wide – making smart machines | Narrow – learning from data |
| Goal | Intelligence/success | Accuracy/pattern learning |
| Includes | ML, expert systems, robotics, NLP | Supervised, unsupervised, reinforcement |
| Example | Self-driving car | Spam detection |

## 3.2 What is Machine Learning? Why Needed? How it Works? (How an ML algorithm works)

**Definition (Tom Mitchell):** A computer program is said to learn from experience **E** with respect to task **T** and performance measure **P**, if its performance on T, measured by P, improves with experience E.

**Simple meaning:** We give the computer lots of data; it finds patterns by itself and uses these patterns to make predictions or decisions on new data.

### Why Machine Learning is Needed
1. **Huge data (Big Data):** Humans cannot analyse such large data manually.
2. **Complex problems without fixed rules:** Image, speech, language recognition cannot be coded with if-else rules.
3. **Automation:** Replaces repetitive manual work.
4. **Personalisation:** Recommendations (YouTube, Amazon).
5. **Better accuracy and speed** in prediction and decisions.
6. **Adapts to change:** Model improves with new data (fraud patterns change).
7. **Discovers hidden patterns** and insights.
8. **Cost saving** and 24x7 operation.

### How Machine Learning Works (steps)
```
 Data --> Data Preparation --> Choose Algorithm --> TRAIN model (learn patterns)
                                                        |
 New Data --> Trained Model --> PREDICTION --> Evaluate --> Improve (loop)
```
1. **Collect data** (e.g., past emails with labels spam/not spam).
2. **Prepare data** – clean, remove errors, select features, split into training and testing sets.
3. **Select an algorithm** – decision tree, linear regression, KNN, SVM, neural network, etc.
4. **Train the model** – the algorithm finds relationship between inputs (features) and output (label) by adjusting parameters to reduce error.
5. **Test/evaluate** on unseen data – measure accuracy, precision, recall.
6. **Tune and improve** – change parameters, add data.
7. **Predict/deploy** – use model on new real data.
8. **Monitor and retrain** as data changes.

## 3.4 Important ML Terms — Training, Testing, Feature, Task, Algorithm, Label, Prediction

1. **Training:** The process of **teaching the model** using a dataset (training data) so it learns patterns and relations. The model's parameters are adjusted to reduce errors. *Training set* is usually ~70-80% of data.
2. **Testing:** After training, the model is checked on **new unseen data (test set)** to measure how well it performs (accuracy). Test set ~20-30% of data. It shows if the model generalises well or has overfitted.
3. **Feature:** An **input variable / attribute / column** used by the model to make a prediction. *Example:* In house-price prediction, features are area, number of rooms, location, age.
4. **Label (Target):** The **output / answer** the model should predict. In supervised learning, training data has labels. *Example:* house price; "spam/not spam"; "cat/dog".
5. **Task:** The **problem the ML model is solving** — e.g., classification, regression, clustering, recommendation, anomaly detection.
6. **Algorithm:** The **step-by-step mathematical method/procedure** used to learn from data — e.g., Linear Regression, Decision Tree, KNN, Naive Bayes, SVM, K-Means. The algorithm + data = model.
7. **Prediction:** The **output given by the trained model for new input data** — e.g., predicting a house price or whether an email is spam.
(Also: **Model** = the learned result of training an algorithm on data.)

**Quick example (email spam):** Features = words in the email, sender, links count; Label = spam/not spam; Algorithm = Naive Bayes; Training = learning from 10,000 labelled emails; Testing = checking on 2,000 new emails; Prediction = classify a new incoming email.

---

## 3.5 Supervised Learning (short note)

**Definition:** In supervised learning the model is trained on **labelled data** — each input has the correct output. The model learns the mapping from input to output, "like a student learning with a teacher". After training it predicts the labels of new data.

```
 Labelled data (X, Y) --> Algorithm --> Trained Model --> New X --> Predicted Y
```

**Types:**
1. **Classification** – output is a category (spam/not spam, disease yes/no). Algorithms: Logistic Regression, Decision Tree, KNN, SVM, Naive Bayes, Random Forest.
2. **Regression** – output is a continuous number (house price, temperature, salary). Algorithms: Linear Regression, Polynomial Regression.

**Examples:** Email spam detection, handwritten digit recognition, house price prediction, credit-risk, medical diagnosis.

**Advantages:** high accuracy, clear results, easy to evaluate.
**Disadvantages:** needs large labelled data (costly), can overfit, cannot discover new unknown classes.

---

## 3.6 Unsupervised Learning (short note)

**Definition:** In unsupervised learning the model works with **unlabelled data** — no correct answers are given. The algorithm itself finds **hidden patterns, groups or structure** in the data, "like a student learning without a teacher".

```
 Unlabelled data (X only) --> Algorithm --> Groups / Patterns / Structure
```

**Types:**
1. **Clustering** – group similar data points (K-Means, Hierarchical, DBSCAN). *Example:* customer segmentation.
2. **Association** – find relations between items (Apriori). *Example:* "People who buy bread also buy butter" (market basket analysis).
3. **Dimensionality reduction** – reduce number of features (PCA).
4. **Anomaly detection** – find unusual data (fraud detection).

**Examples:** Customer segmentation, recommendation systems, grouping news articles, fraud detection, image compression.

**Advantages:** no labelling needed, finds unknown patterns, works with large raw data.
**Disadvantages:** results are harder to evaluate, less accurate, interpretation needed.

## 3.7 Reinforcement Learning; Types / Classification of ML Techniques

### Classification (Types) of Machine Learning
```
                 MACHINE LEARNING
      +-----------------+------------------+
 Supervised        Unsupervised       Reinforcement
 (labelled)        (unlabelled)       (reward/penalty)
  |-Classification  |-Clustering        (+ Semi-supervised: little labelled
  |-Regression      |-Association         + lot of unlabelled data)
                    |-Dim. reduction
```

| Type | Data | Goal | Example |
|---|---|---|---|
| **Supervised** | Labelled | Predict output | Spam detection, price prediction |
| **Unsupervised** | Unlabelled | Find hidden patterns/groups | Customer segmentation |
| **Semi-supervised** | Few labelled + many unlabelled | Better learning with less labels | Web page classification, medical images |
| **Reinforcement** | No data initially; learns by interaction | Maximise total reward | Game AI (AlphaGo), robot walking, self-driving |

### Reinforcement Learning (RL)
- An **agent** interacts with an **environment**, takes **actions**, and receives **rewards** (good) or **penalties** (bad). It learns the best **policy** (strategy) by trial and error to get maximum cumulative reward.
```
  Agent --action--> Environment
    ^                    |
    +--- reward + new state ---+
```
- **Examples:** Chess/Go playing (AlphaGo), robot learning to walk, self-driving cars, game bots, traffic-signal control, ad recommendation.
- **Algorithms:** Q-Learning, SARSA, Deep Q-Network.
- Like training a dog: reward when it does right, no reward/penalty when wrong.

## 3.8 Machine Learning Life Cycle / Workflow / Process (with diagram)

```
 +-------------+    +-------------+    +---------------+    +-------------+
 | 1. Problem  | -> | 2. Data     | -> | 3. Data       | -> | 4. Data     |
 | Definition  |    | Collection  |    | Preparation / |    | Analysis    |
 |             |    |             |    | Cleaning      |    | (EDA)       |
 +-------------+    +-------------+    +---------------+    +------+------+
                                                                    |
 +-------------+    +-------------+    +---------------+    +------v------+
 | 8. Monitor  | <- | 7. Deploy   | <- | 6. Test /     | <- | 5. Train    |
 | & Maintain  |    |             |    |  Evaluate     |    | Model       |
 +------+------+    +-------------+    +-------+-------+    +-------------+
        |  (feedback, retrain)                 | (tune / improve - go back)
        +--------------------------------------+
```

### Phases explained
1. **Problem Definition / Understanding the goal:** Decide what to predict and the business objective (e.g., predict customer churn). Choose success measure.
2. **Data Collection:** Gather data from databases, sensors, websites, APIs, surveys, files. Quality and quantity matter.
3. **Data Preparation (Pre-processing):** Clean data – handle missing values, remove duplicates and noise/outliers, convert types, encode categorical data, normalise/scale, **feature selection/engineering**, and **split** into training / validation / testing sets.
4. **Data Analysis (EDA):** Study patterns, correlations and distributions using statistics and graphs to understand the data.
5. **Model Selection and Training:** Choose a suitable algorithm (regression, decision tree, SVM, neural network) and train on training data so it learns patterns.
6. **Model Testing / Evaluation:** Check on unseen test data with metrics (accuracy, precision, recall, F1, RMSE, confusion matrix). If poor, **tune hyper-parameters**, change algorithm or add data (iterate).
7. **Deployment:** Put the final model into real use (web app, mobile app, API, embedded system).
8. **Monitoring and Maintenance:** Track performance, detect data drift, retrain with new data, and update the model.

**Note:** The process is **iterative** — you often go back to earlier steps to improve.

## 3.12 Main Components of a Machine Learning Model

1. **Data:** The raw material — a dataset divided into **training, validation and testing** sets.
2. **Features (Input variables):** Attributes of data that the model uses to learn.
3. **Label / Target (Output):** The value to predict (in supervised learning).
4. **Algorithm:** The method used to learn the patterns (e.g., Decision Tree).
5. **Model (Parameters/Weights):** The output of training; the learned mathematical function that makes predictions.
6. **Loss (Cost) Function:** Measures how wrong the predictions are (e.g., Mean Squared Error). Training tries to minimise it.
7. **Optimizer:** Updates model parameters to reduce loss (e.g., Gradient Descent).
8. **Hyper-parameters:** Settings chosen before training (learning rate, tree depth, number of epochs).
9. **Evaluation metrics:** Accuracy, precision, recall, F1-score, RMSE — to judge performance.
10. **Prediction/Inference:** Using the trained model on new data.

---

## 3.13 Artificial Neural Networks (ANN) — Structure and Working

**Definition:** An ANN is a computing model **inspired by the human brain's network of neurons**. It consists of interconnected artificial neurons (nodes) arranged in layers that learn from data by adjusting connection weights. It is the foundation of **Deep Learning**.

### Structure
```
   INPUT LAYER       HIDDEN LAYER(S)        OUTPUT LAYER
     (x1) o ------\   /---- o ----\
                   \ /             \
     (x2) o ------- X ----- o ------- o  (output y)
                   / \             /
     (x3) o ------/   \---- o ----/
        Each line = a weight (w)
```
1. **Input layer:** Receives raw data (features); one neuron per feature. No computation.
2. **Hidden layer(s):** Do the computation and learn complex patterns. More hidden layers = deep network.
3. **Output layer:** Gives the final result (class or value).
4. **Weights (w):** Strength of connection between neurons; learned during training.
5. **Bias (b):** An extra constant that shifts the output.
6. **Activation function:** Decides if a neuron "fires" and adds non-linearity — Sigmoid, ReLU, Tanh, Softmax.

### Working of a neuron
`Output = Activation( (x1·w1 + x2·w2 + ... + xn·wn) + b )`

### Working of the ANN (steps)
1. **Initialise** weights randomly.
2. **Forward propagation:** Inputs pass layer by layer; each neuron computes weighted sum + bias and applies the activation function; final layer gives prediction.
3. **Calculate error (loss):** Compare predicted output with actual output.
4. **Back-propagation:** The error is sent backwards, and the gradient of loss with respect to each weight is calculated.
5. **Update weights:** Using an optimizer like Gradient Descent: `w_new = w_old − learning_rate × gradient`.
6. **Repeat** for many **epochs** until error becomes small.
7. **Use** the trained network to predict new data.

### Types
Feed-forward NN, Convolutional NN (images), Recurrent NN/LSTM (sequences, text), Generative adversarial networks.

### Applications
Image and speech recognition, face detection, language translation, medical diagnosis, stock prediction, self-driving cars.

**Advantages:** learn complex non-linear patterns, high accuracy, fault tolerant.
**Disadvantages:** needs lots of data and computing power, "black box" (hard to interpret), long training time.

## 4.9 groupby() Function in Pandas (with example)

**Meaning:** `groupby()` splits the DataFrame into groups based on the values of one or more columns, applies a function (sum, mean, count, etc.) to each group, and combines the result. This is the **Split – Apply – Combine** strategy. It is used for data aggregation.

```
 Split data by key -> Apply function (sum/mean/count) -> Combine results
```
**Syntax:** `df.groupby(by)[column].function()`

**Example:**
```python
import pandas as pd

data = {
    'Department': ['IT', 'HR', 'IT', 'HR', 'Sales', 'Sales'],
    'Employee':   ['A', 'B', 'C', 'D', 'E', 'F'],
    'Salary':     [50000, 40000, 60000, 45000, 35000, 38000]
}
df = pd.DataFrame(data)

print(df.groupby('Department')['Salary'].sum())
print(df.groupby('Department')['Salary'].mean())
print(df.groupby('Department').agg({'Salary': ['min', 'max', 'count']}))
```
**Output (sum):**
```
Department
HR        85000
IT       110000
Sales     73000
Name: Salary, dtype: int64
```
**Output (mean):**
```
HR       42500.0
IT       55000.0
Sales    36500.0
```
**Other uses:** group by multiple columns `df.groupby(['Department','Gender'])`, `.agg()` for many functions, `.size()` for counts, `.get_group('IT')` to get one group, `.transform()`, `.apply()`.

## 4.10 xs() Function in Pandas (with example)

**Meaning:** `DataFrame.xs()` returns a **cross-section** (a particular row or column) from a DataFrame or Series. It is especially useful for selecting data at a particular **level of a MultiIndex (hierarchical index)**.

**Syntax:** `DataFrame.xs(key, axis=0, level=None, drop_level=True)`
- `key` – label or tuple of labels to select
- `axis` – 0 = rows (default), 1 = columns
- `level` – which level of MultiIndex to use
- `drop_level` – if True (default), removes the selected level from the result

**Example:**
```python
import pandas as pd

index = pd.MultiIndex.from_tuples(
    [('IT', 'A'), ('IT', 'B'), ('HR', 'C'), ('HR', 'D')],
    names=['Dept', 'Emp'])
df = pd.DataFrame({'Salary': [50000, 60000, 40000, 45000],
                   'Age': [25, 30, 28, 35]}, index=index)
print(df)
```
```
          Salary  Age
Dept Emp
IT   A     50000   25
     B     60000   30
HR   C     40000   28
     D     45000   35
```
```python
print(df.xs('IT'))                   # all rows of dept IT (Dept level dropped)
print(df.xs('B', level='Emp'))       # rows where Emp = B, any dept
print(df.xs('Salary', axis=1))       # the column 'Salary'
print(df.xs('IT', drop_level=False)) # keep the Dept level
```
**Output of `df.xs('IT')`:**
```
     Salary  Age
Emp
A     50000   25
B     60000   30
```
**Advantage:** easy selection from a specific MultiIndex level without complex slicing.

# UNIT 5: BLOCKCHAIN

## 5.1 Blockchain — Definition, How It Works, Applications (and Cryptocurrency definition)

**Definition:** Blockchain is a **distributed, decentralised, immutable digital ledger** that records transactions in **blocks**; each block is linked to the previous block using a **cryptographic hash**, forming a **chain**. Once data is added it **cannot be altered or deleted**, and the same ledger is stored on many computers (nodes) in a peer-to-peer network, so no central authority (bank) is needed.

**Simple example:** A shared notebook copied to thousands of people. Everyone must agree before a new line is written, and old lines can never be erased.

### Structure of a block
```
 +---------------------+    +---------------------+    +---------------------+
 | Block 1 (Genesis)   | -> | Block 2             | -> | Block 3             |
 | Data / Transactions |    | Data / Transactions |    | Data / Transactions |
 | Timestamp           |    | Timestamp           |    | Timestamp           |
 | Prev Hash: 0000     |    | Prev Hash: hash(B1) |    | Prev Hash: hash(B2) |
 | Hash: A1B2...       |    | Hash: C3D4...       |    | Hash: E5F6...       |
 +---------------------+    +---------------------+    +---------------------+
```
(Block = Data + Timestamp + Nonce + Previous Hash + Own Hash.)

### How Blockchain Works (steps)
1. **Transaction requested:** A wants to send money/data to B.
2. **Transaction broadcast** to the peer-to-peer network of nodes.
3. **Validation:** Nodes verify the transaction (digital signature, balance) using a **consensus algorithm** (PoW/PoS).
4. **Block creation:** Verified transactions are grouped into a new block.
5. **Hashing:** The block gets a unique hash and the previous block's hash is stored in it.
6. **Block added to chain:** After network agreement, the block is attached to the chain.
7. **Ledger updated:** All nodes update their copy; transaction is complete and **permanent**.
If someone changes old data, its hash changes, breaking the chain → fraud is easily detected.

### Applications of Blockchain
1. **Cryptocurrency:** Bitcoin, Ethereum — digital money and payments.
2. **Banking and Finance:** Fast, cheap cross-border payments, trade finance, KYC.
3. **Supply Chain Management:** Track products from origin to customer (food safety, Walmart, IBM Food Trust).
4. **Healthcare:** Secure medical records sharing, drug traceability.
5. **Voting systems:** Transparent, tamper-proof e-voting.
6. **Smart Contracts:** Self-executing agreements (insurance claims, real estate).
7. **Land/Real-estate records:** Prevent fraud in property registry.
8. **Digital identity:** Secure ID management.
9. **Education:** Verification of certificates and degrees.
10. **Intellectual property and Royalty:** Prove ownership of music, art (NFTs).
11. **Government services, Energy trading, Insurance, Gaming.**

(Cryptocurrency definition — see 5.10.)

## 5.2 Benefits and Need of Blockchain

### Need for Blockchain
1. **Removes dependence on middlemen** (banks, brokers) – reduces cost and delay.
2. **Trust problem:** Parties who don't know each other can trade without trusting a central authority.
3. **Data tampering and fraud** in centralised databases (single point of failure/attack).
4. **Lack of transparency** in traditional systems.
5. **Slow and expensive cross-border transfers.**

### Benefits

2. **Transparency** – all participants can see the transactions.
3. **Immutability** – recorded data cannot be changed.

## 5.3 Features of Blockchain

3. **Immutability:** Data once written cannot be edited or removed.
4. **Transparency:** Transactions are visible to participants (public chains).

7. **Anonymity / Pseudonymity:** Users are identified by addresses, not names.
8. **Peer-to-peer network:** Direct transactions between users.
9. **Smart contracts:** Programmable, self-executing agreements.
10. **Traceability/Auditability:** Complete history is time-stamped and traceable.
11. **Fault tolerance:** The network works even if some nodes fail.
12. **Consensus-based trust and Programmability (Tokens/Assets).**

## 5.4 Components and Terminology of Blockchain

### Different Components of Blockchain
1. **Node:** Any computer connected to the blockchain network; stores a copy of the ledger and validates transactions. (Full nodes, light nodes, miner nodes.)
2. **Transaction:** The basic unit of data – transfer of value or information from one party to another.
3. **Block:** A container that stores a group of validated transactions, timestamp, nonce, previous hash and its own hash.
4. **Chain:** Blocks linked in time order through hashes.
5. **Ledger (Distributed ledger):** The complete record of all transactions, shared among all nodes.
6. **Hash (Cryptographic hash function):** A fixed-length unique digital fingerprint of data (e.g., SHA-256). Any tiny change creates a completely different hash.
7. **Digital signature / Public–private keys:** Ensure authenticity and ownership. Private key signs; public key verifies.
8. **Consensus mechanism:** Rule by which nodes agree on the valid state of the chain (PoW, PoS, etc.).
9. **Miners / Validators:** Nodes that verify transactions and create new blocks.
10. **Smart contracts:** Self-executing code stored on the blockchain.
11. **Wallet:** Software/hardware that stores private/public keys and lets users send/receive crypto.
12. **Peer-to-peer (P2P) network:** Connects all nodes without a central server.

### Important Terminologies (brief)
- **Genesis block:** The very first block of a blockchain (no previous hash).
- **Nonce:** "Number used once" – a number miners change to find a valid hash in PoW.
- **Mining:** The process of solving a puzzle to validate a block and earn reward.
- **Fork:** A split/change in the blockchain protocol or chain.
- **Smart contract:** Self-executing program on the blockchain.
- **Merkle tree:** Tree of hashes that efficiently summarises all transactions in a block (Merkle root stored in the block header).
- **Token / Coin:** Digital asset (coin has its own blockchain; token is built on another).
- **Gas:** Fee for executing a transaction/contract on Ethereum.
- **dApp:** Decentralised application.
- **51% attack:** When one entity controls over half the network's power and can manipulate the chain.

## 5.5 Blockchain Transaction — Step by Step

Example: **Alice sends 1 coin to Bob.**
```
 Alice -> [1.Create & Sign] -> [2.Broadcast to P2P network] -> [3.Nodes Validate]
 -> [4.Grouped in a Block] -> [5.Consensus/Mining] -> [6.Block added to chain]
 -> [7.Ledger updated on all nodes] -> Bob receives coin (Confirmed)
```
1. **Initiate:** Alice creates a transaction (sender address, receiver address, amount) using her wallet.
2. **Digital signing:** She signs it with her **private key**, proving she is the owner.
3. **Broadcast:** The transaction is sent to the P2P network and waits in a pool (mempool).
4. **Validation:** Nodes verify the signature (using her public key), check she has sufficient balance and that it isn't double-spent.
5. **Block formation:** Miners/validators collect many valid transactions into a candidate block.
6. **Consensus:** Network agrees on the block (miners solve PoW puzzle or validators are selected in PoS).
7. **Add to blockchain:** The new block with its hash and previous block's hash is attached to the chain.
8. **Update and confirm:** All nodes update their ledger copy; Bob sees the coin. More blocks added later give more confirmations; the transaction becomes permanent/irreversible.

## 5.6 Decentralization

**Definition:** Decentralization means **distributing control, power and decision-making away from a single central authority** to many participants in a network. No single person or organisation controls the whole system.

```
 CENTRALISED            DECENTRALISED            DISTRIBUTED
     o                   o --- o                  o-o-o
   / | \ \               |  \  | \                |\|/|
  o  o  o o            o --- o -- o               o-o-o
 (all depend on         (several hubs)         (every node equal)
  one centre)
```

### Concept in blockchain
- Data and the ledger are stored on **thousands of independent nodes** instead of one central server/bank.
- Decisions (valid or invalid transaction) are taken by **consensus**, not by one authority.
- Nodes communicate peer-to-peer.

### Centralised vs Decentralised
| Point | Centralised | Decentralised |
|---|---|---|
| Control | Single authority (bank, company) | Shared among all nodes |
| Failure | Single point of failure | No single point of failure |
| Transparency | Low | High |
| Security | Central target for hackers | Hard to attack |
| Speed of decision | Fast | Slower (consensus needed) |
| Trust | Trust in authority | Trust in code/network |
| Example | Bank, Facebook | Bitcoin, Ethereum |

**Advantages:** no censorship, higher security and fault tolerance, transparency, lower cost, user ownership of data.
**Disadvantages:** slower, scalability issues, higher energy (PoW), difficult to update/change rules, no one to blame/reverse mistakes.

## 5.7 Types of Blockchain (Public, Private, Hybrid/Consortium) and Public vs Private

### 1. Public Blockchain (Permissionless)
- **Anyone** can join, read, write and take part in consensus. No permission needed.
- Fully decentralised and transparent; usually uses PoW/PoS; slower and costly.
- **Examples:** Bitcoin, Ethereum, Litecoin.
- **Use:** cryptocurrencies, open DeFi, public voting.

### 2. Private Blockchain (Permissioned)
- Controlled by **a single organisation**; only invited/authorised participants can join, and the owner controls who can read/write/validate.
- Faster, more scalable, more private; less decentralised; lower trust (central control).
- **Examples:** Hyperledger Fabric (used privately), Multichain, R3 Corda (private use), company internal ledgers.
- **Use:** internal audit, supply chain within a company, banking records.

### 3. Hybrid Blockchain
- Combination of public and private: some data is kept private and some is public. Organisation decides what is visible and what needs access permissions.
- **Examples:** IBM Food Trust, XinFin / Dragonchain.
- **Use:** real estate, medical records with controlled sharing.

### 4. Consortium (Federated) Blockchain
- Controlled by **a group of organisations** instead of one; pre-selected nodes validate transactions. Semi-decentralised.
- **Examples:** Hyperledger, R3 Corda, Energy Web Foundation, banking consortium.
- **Use:** inter-bank transfers, supply chain among multiple companies.

```
 Public  <-------------- Hybrid / Consortium --------------> Private
 Open to all   Partly open/Group-controlled                  One owner
```

### Difference: Public vs Private Blockchain
| Point | Public | Private |
|---|---|---|
| Access | Anyone can join | Only authorised members |
| Control | Fully decentralised | Controlled by one organisation |
| Consensus | PoW, PoS | PBFT, Raft, simple voting |
| Speed | Slower | Faster |
| Transparency | High | Limited |
| Scalability | Low | High |
| Energy/Cost | High | Low |
| Privacy | Low (data visible) | High |
| Security risk | 51% attack hard but possible | Insider/central-control risk |
| Example | Bitcoin, Ethereum | Hyperledger, Corda (private) |

**Two types with examples (for answer):** Public – Bitcoin; Private – Hyperledger Fabric (company-controlled supply-chain).

## 5.8 Blockchain Architecture (with diagram)

**Meaning:** Blockchain architecture is the overall structure and layers of a blockchain system – how nodes, blocks, network, consensus and applications work together.

```
 +-------------------------------------------------------------+
 | 5. APPLICATION LAYER   (dApps, wallets, smart-contract UI)  |
 +-------------------------------------------------------------+
 | 4. CONTRACT / EXECUTION LAYER (smart contracts, VM)         |
 +-------------------------------------------------------------+
 | 3. CONSENSUS LAYER     (PoW, PoS, PBFT - agree on blocks)   |
 +-------------------------------------------------------------+
 | 2. NETWORK LAYER       (P2P nodes, propagation of tx/blocks)|
 +-------------------------------------------------------------+
 | 1. DATA LAYER          (blocks, transactions, hashes,       |
 |                         Merkle tree, ledger, cryptography)  |
 +-------------------------------------------------------------+
```

**Block structure (data layer):**
```
 +-------------------- BLOCK ----------------------+
 | HEADER:  Previous Block Hash | Timestamp |     |
 |          Nonce | Merkle Root | Difficulty      |
 | BODY:    Transaction 1, Transaction 2, ... n   |
 +------------------------------------------------+
 Block N-1 <--hash link-- Block N --hash link--> Block N+1
```

**P2P network architecture:**
```
     Node A ---- Node B
       |  \     /  |      Every node keeps a full/partial
       |   Node E  |      copy of the ledger; no central server
     Node D ---- Node C
```

### Components / Layers explained
1. **Data layer:** Contains blocks, transactions, Merkle tree, hash pointers, ledger and cryptographic functions (SHA-256, digital signatures).
2. **Network layer (P2P):** Nodes communicate, broadcast new transactions and blocks, and synchronise the ledger.
3. **Consensus layer:** Ensures all nodes agree on a single valid chain (PoW, PoS, DPoS, PBFT).
4. **Contract / Execution layer:** Runs smart contracts (e.g., Ethereum Virtual Machine) and defines business rules.
5. **Application layer:** User-facing apps (wallets, dApps, exchanges, APIs) that interact with the blockchain.

### Key elements
Nodes, Transactions, Blocks (header + body), Ledger, Consensus protocol, Cryptography (hash + keys), Smart contracts, Wallets, Miners/Validators.

**Working:** User makes transaction → broadcast on network → validated by nodes → consensus → added into a block → linked to chain → ledger updated everywhere.

## 5.9 Consensus Algorithms — PoW, PoS and Others

**Consensus algorithm:** The rule/method by which all nodes in a decentralised network **agree on the valid state of the ledger** (which transactions and blocks are correct) without trusting any central authority. It prevents **double spending** and fraud.

### Proof of Work (PoW)
- Used by **Bitcoin** (and earlier Ethereum).
- **Working:**
  1. Miners collect pending transactions into a candidate block.
  2. They must find a **nonce** such that the block's hash is below a target (e.g., starts with many zeros) – by trial and error (requires huge computing power).
  3. The first miner to solve the puzzle broadcasts the block with the "proof of work".
  4. Other nodes quickly **verify** the solution (easy to check, hard to find).
  5. Block is accepted and added; miner gets a **block reward + transaction fees**.
- **Advantages:** very secure (51% attack extremely costly), proven, decentralised.
- **Disadvantages:** very high electricity consumption, slow (Bitcoin ~7 tx/sec), expensive hardware (ASIC), centralisation of mining pools.

### Proof of Stake (PoS)
*(Questions write "Proof of Stack" — the correct term is **Proof of Stake**.)*
- Used by **Ethereum 2.0 (since 2022 "Merge")**, Cardano, Solana, Polkadot.
- **Working:**
  1. Participants (**validators**) **lock (stake) some of their coins** as a security deposit.
  2. The protocol selects a validator to create the next block — chosen randomly, weighted by the size and age of stake.
  3. The validator proposes the block; other validators attest (verify) it.
  4. If honest, the validator earns **rewards (fees / new coins)**; if dishonest, part of their stake is **slashed** (lost).
- **Advantages:** very low energy use, faster, cheaper, more scalable, no expensive hardware, encourages honesty.
- **Disadvantages:** "rich get richer" (large holders have more power), risk of centralisation, "nothing at stake" problem, newer and less tested than PoW.

### Comparison PoW vs PoS
| Point | PoW | PoS |
|---|---|---|
| Selection | Solve puzzle (computing power) | Stake (coins held) |
| Energy | Very high | Very low |
| Speed | Slow | Faster |
| Hardware | Costly (ASIC, GPU) | Normal computer |
| Reward | Block reward to miner | Fees/rewards to validator |
| Attack | 51% hash power | 51% of stake |
| Example | Bitcoin | Ethereum 2.0, Cardano |

### Other Consensus Algorithms (brief, for "list/explain different")
1. **Delegated Proof of Stake (DPoS):** Coin holders vote for a few delegates who validate blocks (EOS, TRON). Fast but less decentralised.
2. **Proof of Authority (PoA):** Pre-approved trusted validators using their identity/reputation; fast, used in private chains.
3. **Practical Byzantine Fault Tolerance (PBFT):** Nodes exchange messages and vote; tolerates up to 1/3 faulty nodes. Used in Hyperledger Fabric.
4. **Proof of Capacity / Space:** Uses disk space to "plot" solutions (Chia).
5. **Proof of Burn (PoB):** Validators burn (destroy) coins to get mining rights.
6. **Proof of Elapsed Time (PoET):** Each node waits a random time; shortest wait wins (Intel SGX; Hyperledger Sawtooth).
7. **Proof of History (PoH):** Cryptographic timestamps order events (Solana).
8. **Raft / Paxos:** Leader-based crash-fault-tolerant consensus for private networks.

## 5.10 Cryptocurrency, Altcoins, Forking

### Cryptocurrency
**Definition:** A cryptocurrency is a **digital/virtual currency** that uses **cryptography** for security, works on **blockchain (decentralised network)**, and is not issued or controlled by any government or central bank. Units are created through mining or staking, and transferred peer-to-peer using wallets.
**Examples:** Bitcoin (BTC), Ethereum (ETH), Ripple (XRP), Litecoin (LTC), Dogecoin.
**Features:** decentralised, secure, pseudonymous, limited supply (e.g., 21 million BTC), borderless, fast international transfer, irreversible transactions, divisible.
**Types:** Coins (own blockchain – BTC, ETH), Tokens (built on another blockchain – USDT, UNI), Stablecoins (value tied to fiat – USDT, USDC), Utility tokens, Security tokens, Governance tokens, Meme coins, CBDC (government-issued).

### Altcoins (brief)
**Meaning:** "Alternative coins" — **all cryptocurrencies other than Bitcoin**. Created after Bitcoin (2009) to improve or change its features such as speed, cost, privacy, smart-contracts, energy use.
**Types:**
1. **Mining-based coins (PoW):** Litecoin, Bitcoin Cash, Monero.
2. **Stablecoins:** Tether (USDT), USD Coin (USDC) — price pegged to USD.
3. **Security tokens:** Represent ownership in an asset/company.
4. **Utility tokens:** Give access to a service (Binance Coin, Basic Attention Token).
5. **Platform/Smart-contract coins:** Ethereum, Cardano, Solana, Polkadot.
6. **Privacy coins:** Monero, Zcash.
7. **Meme coins:** Dogecoin, Shiba Inu.
**Examples with purpose:** Litecoin – faster than Bitcoin; Ethereum – smart contracts and dApps; Ripple (XRP) – quick bank payments; Monero – privacy.
**Advantages:** improved features, variety, cheaper/faster transactions. **Risks:** very volatile, scams, low liquidity.

### Types of Forking (Fork)
**Fork:** A **change in the blockchain's protocol rules or a split of the chain** into two paths. It happens when developers upgrade software, fix problems, or when the community disagrees.

```
 Hard fork:   ---B1---B2---B3---B4---(old chain)
                          \
                           ---B4'--B5'---(new chain - separate coin)

 Soft fork:   ---B1---B2---B3---B4---B5---  (single chain, old nodes still accepted)
```
1. **Hard Fork:**
   - A **permanent, non-backward-compatible** change; old nodes **cannot** validate new blocks. If all do not upgrade, the chain **splits into two** separate blockchains and often a new coin.
   - *Examples:* Bitcoin → **Bitcoin Cash (2017)**; Ethereum → **Ethereum Classic (2016, DAO attack)**.
   - Types: **Planned** (scheduled upgrade for all) and **Contentious** (community disagreement, creating a new coin).
2. **Soft Fork:**
   - A **backward-compatible** upgrade; old nodes still accept the new blocks (new rules are stricter). Usually **no split**; majority of miners must upgrade.
   - *Example:* Bitcoin **SegWit (2017)**.
3. **Other types (if asked):**
   - **Accidental fork / Temporary fork:** Two miners find a block at the same time; resolved when the longer chain is accepted (orphan blocks).
   - **User-activated soft fork (UASF)** and **Miner-activated soft fork (MASF).**

| Point | Hard Fork | Soft Fork |
|---|---|---|
| Compatibility | Not backward compatible | Backward compatible |
| Result | Chain splits, new coin | No split |
| Upgrade needed | All nodes | Majority of miners |
| Example | Bitcoin Cash | SegWit |
